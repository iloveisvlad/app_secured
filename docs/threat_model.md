# Упрощенная модель угроз

## Активы

```text
- исходный код и dockerfile;
- container images;
- переменные окружения и секреты;
- база данных postgres;
- очередь redis;
- пользовательские вложения;
- файлы экспортированных отчетов;
- docker host.
```

## Основные риски учебного стенда

### Риски образов

В уязвимой версии используются тяжелые образы, лишние пакеты, запуск от root, отсутствие healthcheck, отсутствие .dockerignore и демонстрационный секрет в build context. Это создает основу для последующего сравнения после image hardening.

### Риски runtime

Compose-файл не задает read_only, cap_drop, no-new-privileges, pids_limit и memory limits. Контейнеры получают больше возможностей, чем нужно приложению.

### Сетевые риски

PostgreSQL и Redis опубликованы на host-порты. Все сервисы находятся в одной сети. Это моделирует типовую ошибку, когда внутренние сервисы становятся доступными вне контейнерного контура.

### Риски секретов

JWT secret, database password и demo token находятся прямо в docker-compose и .env.example. В дальнейшем они должны быть вынесены из образа и репозитория.

### Риски хранения данных

Uploads и reports подключены грубыми bind mounts. В защищенной версии это должно быть пересмотрено с учетом минимально необходимых прав и read-only root filesystem.

## Что намеренно не моделируется

```text
- sql injection;
- xss;
- rce;
- ssrf;
- docker socket mount;
- privileged container;
- kubernetes-specific risks.
```

Эти риски не включены, чтобы стенд оставался безопасным для учебного запуска и соответствовал теме контейнерного hardening.
